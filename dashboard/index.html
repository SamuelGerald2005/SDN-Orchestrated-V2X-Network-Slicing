    What the testbed is

    Six vehicles drive between two roadside units (RSUs). Each RSU is an Open vSwitch access point with an edge (MEC) server attached. Both RSUs connect over a 20 Mb/s, 5 ms backhaul to an aggregation switch, s1, which leads to a central infotainment server and a telemetry server (15 ms away). A RYU application, the orchestrator, controls all three switches over OpenFlow 1.3.

    The five slices

    What happens to a packet

    1. Classify. Table 0 on every switch matches the packet's protocol and port and assigns it to a slice. Anything that matches no slice is best effort.
    2. Police. The packet passes through its slice's OpenFlow meter. Above the slice's budget, packets are dropped, so one slice can't take another's bandwidth.
    3. Mark. The switch writes a DSCP value into the packet. On the backhaul links, three strict-priority queues read it: URLLC and platoon first, mMTC second, eMBB and best effort last.
    4. Forward. Table 1 learns where each vehicle is. When a vehicle appears behind a different port, that's a handover: old flows are deleted everywhere so traffic follows the vehicle.

    The threshold loop

    Every 2 seconds the orchestrator reads each meter's byte counter and works out each slice's rate. If critical traffic (URLLC + platoon) plus eMBB would overflow the 20 Mb/s backhaul, it lowers the eMBB meter to what's left (PROTECT_ON, then ADJUST as the load changes), and restores it when the critical slices go quiet (PROTECT_OFF). eMBB is never squeezed below 2 Mb/s.
