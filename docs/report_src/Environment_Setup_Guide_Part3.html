Environment Setup Guide, Part 3

Native Ubuntu migration, the project image, and running the full testbed
SDN-Orchestrated Network Slicing for Vehicular 5G (V2X). November 2026.

Parts 1 and 2 set the testbed up inside a VirtualBox VM on Windows. This part covers the move to a dedicated Ubuntu laptop, rebuilding the images, and the scripts that now run every check and experiment. It continues the step numbering from Part 2.

The user is not in the docker group, so every Docker command needs sudo. That is why each script below asks for the password once at the start.

Step 15: Base image mn-wifi:v1

Clone Mininet-WiFi and patch its Dockerfile before building. The base image is python:3.9, now Debian 13. Insert these two lines before RUN util/install.sh -Wlnfv6:

RUN sed -i "s/from FlightRadarAPI import FlightRadar24API/from FlightRadar24 import FlightRadar24API/" mn_wifi/net.py
RUN sed -i "s/matplotlib.use('TkAgg')/matplotlib.use('TkAgg', force=False)/" mn_wifi/telemetry.py
  • FlightRadar fix. FlightRadarAPI 1.4.1 and later need Python 3.10. On 3.9, pip installs 1.4.0, whose module is named FlightRadar24.
  • TkAgg fix. Upstream now forces the Tk plotting backend at import, which crashes the headless Docker build.
  • The set_data([x],[y]) patches from Part 1 Step 7.3 are no longer needed; upstream fixed them.
git clone https://github.com/intrig-unicamp/mininet-wifi ~/mininet-wifi
cd ~/mininet-wifi && sudo docker build -t mn-wifi:v1 .

Step 16: Project image mn-wifi:v2

Built from ~/v2x-project/docker/Dockerfile. It adds RYU, restores Mininet-WiFi's mn, and installs iperf3:

FROM mn-wifi:v1
RUN python3 -m pip install "setuptools<68" wheel \
 && python3 -m pip install --no-build-isolation ryu \
 && python3 -m pip install "eventlet==0.30.2"
RUN install -m 755 /app/mininet-wifi/bin/mn /usr/local/bin/mn
RUN apt-get update && apt-get install -y iperf3 && rm -rf /var/lib/apt/lists/*
WORKDIR /app/project
  • RYU 4.34 pins. setuptools<68 because get_script_args was removed; --no-build-isolation so that pin applies; eventlet 0.30.2 because ALREADY_HANDLED was removed later.
  • mn restore. Plain Mininet's mn overwrote Mininet-WiFi's, so mn --wifi failed until it was reinstalled.
cd ~/v2x-project/docker && sudo docker build -t mn-wifi:v2 .

Step 17: Running the testbed

17.1 Manual session (two terminals)

The original launch script, ~/start_mnwifi.sh, starts a privileged container with the project folder mounted at /app/project. Everything else in the container is lost on exit.

~/start_mnwifi.sh
mn -c
ryu-manager --wsapi-port 8081 /app/project/controller/v2x_orchestrator.py

In a second terminal:

sudo docker exec -it $(sudo docker ps -q --filter ancestor=mn-wifi:v2) bash
python3 /app/project/v2x_topology_v2.py

Always run mn -c before starting RYU, because mn -c kills ryu-manager. Wait about 25 seconds for the scripted mobility to finish before measuring.

All of these run from ~/v2x-project, keep their logs under logs/, and hand the files back to your user when they finish.

17.3 Dashboard

python3 ~/v2x-project/dashboard/server.py

Then open http://127.0.0.1:8090. It needs no sudo, no Docker and no internet, and replays the recordings in dashboard/recordings.
