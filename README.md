# SDN-Orchestrated Network Slicing for Vehicular 5G (V2X)

Mininet-WiFi + RYU 4.34 (OpenFlow 1.3) + Open vSwitch, run in Docker on Ubuntu.
Team: A. Adharsh, Rishabh Bhat, Samuel Gerald.

Six vehicles move between two roadside units (RSUs). Each RSU has an edge (MEC)
server, and both connect over a 20 Mb/s backhaul to an aggregation switch and the
central servers. A RYU application, the orchestrator, runs five slices: it
classifies traffic, polices each slice with an OpenFlow meter, marks packets for
strict-priority queues, follows vehicles across handovers, and adapts the eMBB
budget to what the backhaul has left.

## Layout

| Path | What it is |
|---|---|
| `controller/v2x_orchestrator.py` | The orchestrator (RYU app) and its REST API on port 8081 |
| `v2x_topology_v2.py` | The topology: RSUs, vehicles, MEC and central servers, links, priority queues, mobility |
| `experiments/udp_probe.py` | Per-slice UDP probe: RTT, jitter, loss, delivery gaps |
| `experiments/analyze.py` | Turns experiment logs into `trials.csv`, `summary.md` and `results.json` |
| `experiments/figures.py`, `run_figures.py` | Report figures from `results.json` and from the dashboard recordings |
| `dashboard/` | The dashboard (`server.py`, `index.html`, `app.js`) and its recordings |
| `scripts/` | Batch scripts that run everything inside the container |
| `docker/Dockerfile` | The `mn-wifi:v2` image |
| `docs/` | `V2X_Evaluator_Explanation.pdf` (start here), `V2X_Evaluation_II.pptx` (slides), `V2X_HANDOFF_v2.md`, setup guide Part 3, progress report, `figures/` |
| `results/` | Analysis of the 80 trials (`summary.md`, `trials.csv`, `results.json`) and the functional-test outputs |
| `paper/` | The conference paper draft (LaTeX), with the data behind each plot |
| `logs/` | Raw logs of every run (not in git; regenerated by the scripts) |

## Two ways to use this repository

| | What you get | What you need |
|---|---|---|
| **A. Dashboard replay** | The full dashboard with four recorded runs (vehicles moving, per-slice rates, latency, controller events) and the results of all 80 experiment trials | Any computer with **Python 3**. Nothing to install, no internet, no Docker |
| **B. Live testbed and experiments** | The real emulated network: run the orchestrator, watch it live on the dashboard, repeat the experiments | **Linux** with Docker, `sudo`, and the kernel modules `mac80211_hwsim` and `openvswitch`; about 4 GB of disk for the images |

Download or clone the repository, then `cd` into its folder. All commands below are run from there.

## A. Run the dashboard (no installation)

```bash
python3 dashboard/server.py
```

Then open http://127.0.0.1:8090 in a browser. (On Windows use `python dashboard\server.py`.)

- **Run** tab: pick a recording, optionally a second one under "Compare with", press Play. Speed 4 suits a demo.
- **Experiment results** tab: bars and tables for every scenario and setup (5 repeats each).
- **How it works** tab: the architecture and slice explanation.
- Direct links open a chosen moment, e.g.
  `http://127.0.0.1:8090/?rec=scripted_best_effort&cmp=scripted_orchestrated&t=55` or
  `http://127.0.0.1:8090/?view=results&scenario=heavy`.

The "Live testbed" entry in the Recording list stays empty unless you also run part B.

## B. Run the testbed (Linux, Docker)

Check the kernel modules once (the host's own Open vSwitch service must stay stopped):

```bash
sudo modprobe mac80211_hwsim openvswitch && lsmod | grep -E 'hwsim|openvswitch'
```

Build the two Docker images (about 20 to 40 minutes; this follows `docs/Environment_Setup_Guide_Part3.pdf`,
steps 15 and 16, and clones Mininet-WiFi from GitHub, so upstream changes can break it):

```bash
sudo bash scripts/build_images.sh
```

Run the testbed live and watch it on the dashboard (two terminals):

```bash
sudo bash scripts/run_live_demo_host.sh orchestrated 30
```

```bash
python3 dashboard/server.py
```

Pick "Live testbed" in the Recording list. Use `best_effort` or `static` in place of `orchestrated` to compare.

Run everything again from scratch (functional checks, recordings, 5 experiment repeats, about 3.5 hours):

```bash
sudo bash scripts/run_all_host.sh 5
```

```bash
python3 experiments/analyze.py logs/step2 && cp logs/step2/results.json dashboard/
```

Manual session (two terminals into the container):

```bash
bash scripts/start_mnwifi.sh
```

Inside it: `mn -c`, then `ryu-manager --wsapi-port 8081 /app/project/controller/v2x_orchestrator.py`.
In a second terminal, `sudo docker exec -it $(sudo docker ps -q --filter ancestor=mn-wifi:v2) bash`,
then `python3 /app/project/v2x_topology_v2.py`.

The scripts write their files as root inside the container and hand them back to your user when they finish.
The documents in `docs/` use `~/v2x-project` as the example location; use wherever you put the repository.

## Results (5 repeats, 95th percentile RTT during an eMBB flood)

| | Best effort | Meters only | Meters + loop | Meters + priority | Orchestrated |
|---|---|---|---|---|---|
| Congestion, platoon | 3795 ms | 25.5 ms | 25.5 ms | 24.9 ms | 24.9 ms |
| Heavy load, platoon | 702 ms | 203 ms | 24.4 ms | 23.3 ms | 23.2 ms |

Full tables: `results/summary.md`. Known limitation: a 7 to 14 s gap at each
handover in every setup, from the emulated Wi-Fi re-association (see `docs/V2X_HANDOFF_v2.md`).

## Controller switches (environment variables)

| Variable | Effect |
|---|---|
| `V2X_SLICING=0` | Best effort: no meters, no marking, no loop |
| `V2X_PRIORITY=0` | Meters but no DSCP marking, so all traffic shares one queue band |
| `V2X_DYNAMIC=0` | Threshold loop off (static budgets) |
| `V2X_POLICY=fixed` | The earlier loop policy: halve eMBB whenever critical traffic appears |

## Topology switches

| Variable | Effect |
|---|---|
| `V2X_MOBILITY=random` | Random waypoint mobility (seed `V2X_SEED`) instead of the scripted paths |
| `V2X_PLOT=0` | No live Mininet-WiFi plot |
| `V2X_TRACE=<dir>` | Write positions for the dashboard |
